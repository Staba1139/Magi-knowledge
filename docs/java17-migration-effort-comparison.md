# Java 17 移行 工数比較レポート

## 概要

本ドキュメントは、Magi-knowledge プロジェクトにおける Java 17 移行作業について、**人力のみで開発した場合**と**Claude Codeを活用した場合**の工数を比較・分析したものである。

## 移行作業の規模

| 項目 | 数値 |
|---|---|
| 変更コミット数 | 7コミット（ドキュメント除くと実質6コミット） |
| 変更ファイル数 | 48ファイル |
| 追加行数 | +1,866行 |
| 削除行数 | -1,116行 |

### 主な移行内容

1. **ビルド/依存関係の移行** — pom.xml書き換え、Bower→Maven WebJars移行、Java 17対応
2. **Jackson XML修正** — Tomcatデプロイ失敗のデバッグ・修正
3. **ライブラリバージョン更新** — Lucene 9.x, Tika 3.x, H2 2.x等
4. **commons-lang 2.x→3.x移行** — import文・API呼び出しの書き換え
5. **Lucene 4.x→9.x移行** — 検索・インデックスAPIの全面書き換え
6. **H2 2.x SQL移行** — SERIAL/BIGSERIAL→IDENTITY列への書き換え
7. **ドキュメント作成** — 移行レポート、README更新

## カテゴリ別 工数比較

| カテゴリ | 人力のみ | Claude Code活用 | 自動化率 | 備考 |
|---|---|---|---|---|
| ビルド/依存関係の移行 | 3〜5人日 | 0.5〜1人日 | 80% | pom.xml書き換え・Bower除去はClaude Codeが得意 |
| Jackson XML修正 | 1〜2人日 | 0.5〜1人日 | 50% | エラー原因の特定にはログ確認等の人的判断が必要 |
| ライブラリバージョン更新 | 0.5人日 | 0.1人日 | 90% | 単純な書き換え、ほぼ自動化可能 |
| commons-lang3移行 | 0.5〜1人日 | 0.1人日 | 95% | import文の機械的な置換 |
| Lucene 4.x→9.x移行 | 3〜5人日 | 0.5〜1人日 | 80% | API差分の知識に基づく書き換え |
| H2 2.x SQL移行 | 1〜2人日 | 0.2〜0.5人日 | 85% | SERIAL→IDENTITYの規則的な置換 |
| ドキュメント作成 | 1人日 | 0.1〜0.2人日 | 90% | 差分の要約・レポート生成 |

## 追加考慮事項の比較

| 作業 | 人力のみ | Claude Code活用 | 備考 |
|---|---|---|---|
| 調査・検証 | 2〜3人日 | 0.5〜1人日 | 破壊的変更の洗い出しをClaude Codeが支援 |
| テスト・デバッグ | 3〜5人日 | 1〜2人日 | ビルド実行・エラー修正のループは人の確認が必要 |
| CVE対応の調査 | 1〜2人日 | 0.2〜0.5人日 | 脆弱性情報の検索・対処方針の提案が可能 |

## 合計工数の比較

| | 人力のみ | Claude Code活用 | 削減率 |
|---|---|---|---|
| 最小工数 | 16人日 | 3.7人日 | **約77%削減** |
| 最大工数 | 26人日 | 7.3人日 | **約72%削減** |
| 期間（1人作業） | 3〜6週間 | 1〜1.5週間 | **約75%短縮** |

## Claude Codeが特に効果を発揮する領域

- **機械的な置換作業**: import文変更、SQL文のSERIAL→IDENTITY変換など
- **API移行**: Luceneなどの旧→新APIの書き換えパターンを知識として保持
- **pom.xml編集**: 依存関係の追加・削除・バージョン変更
- **ドキュメント生成**: 変更内容の要約・レポート作成

## 人の判断が依然必要な領域

- **ビルド・デプロイの実行確認**: 実環境での動作検証
- **ランタイムエラーのデバッグ**: ログを読み原因を切り分ける判断
- **移行方針の意思決定**: どのバージョンを採用するか等の設計判断

## 結論

Claude Codeを活用することで、Java 17移行作業の工数を約 **70〜80%** 削減できる。特に調査・コード書き換え・ドキュメント作成のフェーズで大幅な効率化が見込まれる。一方で、ビルド・デプロイの動作確認や、ランタイムエラーのデバッグなど、実環境に依存する作業には引き続き人的判断が不可欠である。
